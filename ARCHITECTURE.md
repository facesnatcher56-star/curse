# Architecture

A Godot 4 click-to-move ARPG: fixed 3/4 camera, weighty melee, wave arena. Scripts live in `game/`, tunable data in `data/`.

## Common-character milestone (in progress)

`CharacterState` is the common persistent character record, independent of campaign/world state.
`id` identifies the character; `owner_id` identifies its persistent human profile. Neither
changes when control switches. Exporting this record carries progression, gear, purchases,
hotbar configuration and power/vital state, not quests, world state or party resources.

`PartyManager` holds a variable roster capped at six, the shared backpack, resource access,
live body lookup, controller subgroups and each controller's active member. Subgroup assignment
validates 1×6, 2×3 or 3×2 capacity and rejects duplicate character assignment. Controller IDs
are runtime authorities, not character owner IDs. The current milestone instantiates only
Hero and Cutter locally; no network transport, joining UI or authority protocol is implemented.

Both bodies use `Player`, `PlayerStats`, `SkillController`, `PowerController` and the existing
DS2 rules. `PartyCharacterAI` supplies orders through the same movement/attacks. `BowAttack`
owns the shared equipped-bow action and extracted archery presentation. `ArcherCompanion`
is a compatibility/presentation subclass, not an independent combat or progression system.
Character presentation data selects rigs; it does not gate combat disciplines.

Switching is subgroup-scoped, without body replacement. Portraits, C, and Left Trigger select
the local active member (bindings are editable). Delayed combat results capture
`{character_id, owner_id}`; projectiles and burns retain this provenance across selection.
Summoned actors have the same provenance hook, but player summons/networking are not added here.

Save version 11 follows the existing legacy migration chain. It preserves Hero XP, all class
XP, purchased passives, equipment and legacy settings hotbars; Cutter's old XP becomes independent
character and Ranged XP. Unspent points remain derived from the existing shared rule.
Cutter receives a standard level-2 bow, not a permanent equipment exemption or free Take Aim.
Backpack items and their layout are serialized once by the party. Development checks use
SavePolicy's developer directory; production saving remains disabled.

Verification commands and remaining acceptance work: [Phase 0 status](docs/PARTY_PHASE0_STATUS.md).

## Shared obstacle routing

`Nav.route` returns FOLLOWING, ARRIVED, WAITING or UNREACHABLE plus an explicit waypoint.
Human click movement, common-character companion orders and enemy chase/retreat/circling
consume this service. No failed-query direct steering or distance-based navigation bypass
is allowed. Paths are retained while FIFO replacement queries wait; all runtime route
queries, including retries, share a four-query-per-physics-tick limit. Map iteration changes
invalidate caches. Body-sized world sweeps validate segments; corner skipping and an
unvalidated final leg are not used. One second without actual movement starts replanning;
five seconds with two unsuccessful replans stops sustained pushing and uses one-second retries.

Arena, town and road bake collider geometry with 0.75 m agent clearance.
Solid prop collider footprints also supply height-extruded bake exclusions: characters are
constrained to y=0, so Recast must not offer routes over rubble slopes, cart tops or roofs.
Exclusions are children of the prop, disappear with it, and retain the bake's agent-radius margin.
Unreachable companion formation queries fall back to the leader without bypassing the query cap.
Map iteration
builds are synchronous to avoid the reproduced empty initial map in this engine build;
destruction rebakes remain asynchronous. Readiness requires usable map-level region ownership,
not merely a nonzero iteration. Destruction during a bake schedules a subsequent bake.

Companion catch-up is rescue-only: over 30 m apart, five seconds failed progress, two failed
replans, both endpoints off-camera, no committed action/death/incapacitation. Candidates
come from recorded leader breadcrumbs, must be collision-free (including actors), and require
a clear body-sized connection to the leader. This conservative reachability proof can reject
an otherwise reachable breadcrumb around a corner; the companion waits instead of guessing.
Each body owns its route cache; revival, rescue and teardown reset it. Control switching
does not transfer caches. Basic melee/bow attacks check solid-world line of sight.

Checks, evidence and remaining acceptance gaps: [navigation verification](docs/NAVIGATION_VERIFICATION.md).

## Layout

| Path | What lives there |
| --- | --- |
| `game/main.gd` | Builds the world (arena, hero, camera, HUD, menus) and creates the `RunDirector`. ~4 KB. |
| `game/run/run_director.gd` | The run: wave composition and spawning, kill tracking, the reward offered between waves. |
| `game/player.gd` | The hero node: input, cursor picking, orchestration of the components below, hit hooks. |
| `game/player/` | `PlayerStats` (mana/stamina/potions, cooldowns, equipment, regen), `PlayerMovement` (click-to-move, locomotion animation, dodge roll), `SkillController` (hotkeys, aim preview, starting/ticking skills, combo, strike effects). |
| `game/enemy.gd`, `game/enemies/` | `Enemy` is the shared body (stats from its `EnemyDef`, aggro/stun, movement helpers, attack slots). `EnemyBehavior` subclasses decide what it does: `MeleeBehavior`, `PouncerBehavior`, `SpitterBehavior`, `BloaterBehavior`, `SupportBehavior`. `AcidGlob` and `HazardZone` are their effects. |
| `game/enemies/champion.gd` | `Champion`: a pack's tougher, named member with one affix from `Champion.AFFIXES` (Fast, Shielded, Summoner, Volatile). Hooks for other spawners: `Champion.roll_pack(members)` (called by the wave packs and the Crypt Road's groups), `Champion.attach(enemy, affix)`, `Champion.loot(...)`. An enemy keeps it in `Enemy.champion`. See [COMBAT_REFERENCE](docs/COMBAT_REFERENCE.md#champions-curse-addition-owner-roadmap-34-not-a-ds2-mechanic). |
| `game/actor.gd` | Base of hero and enemies: health, hit reaction, burn/frost/ward/daze, ragdoll, gib bursts. Living knockback and ragdoll collisions are presentation only: no automatic damage, extra stun, chain knockdown, status transfer or collision XP; `apply_snare` is the slow ranged monsters get when hit while backing away (`snare_on_hit` in their `EnemyDef` params). |
| `game/data/` | Resource classes (`EnemyDef`, `SkillDef`, `ItemDef`, ...) and their loaders (`EnemyDb`, `SkillDb`, `ItemDb`, ...). |
| `data/` | The `.tres` files those loaders read: `data/enemies`, `data/skills`, `data/items`, ... |
| `game/ground_look.gd` | The ground shader (`GroundLook.material`): four scales of noise in world space (broad stains, clods and cracks from a cellular noise, gravel, grit) with the relief worked out from the same heights, so the plaza's earth and the Crypt Road's ribbon (`edge_fade`, fades with vertex alpha) are detailed down to a few centimetres and join without a seam. Replaced the single stretched noise texture. |
| `tools/author_attack_anims.gd` | Authors the basic-attack clips on the Knight's own rig (`godot --headless --path . --script tools/author_attack_anims.gd`, rewrites the `atk_*` and `atk2_*` clips in `assets/models/knight2/anims.res`). `atk_*` are the Meshy swings with body motion layered on (hips and chest coil and drive, lean, knees take the weight, head stays on the target); `atk2_*` are for two-handers (`two_hand_clips` in a weapon's profile): both arms are solved so both hands stay on the grip. Basic swings have no blade ribbon any more (Power Strike keeps its own). Look at them with `-- --clipsheet=NAME --closeup [--equip=Greatsword]`. Test: `--only=twohand`. |
| `tools/blender/make_fists.py`, `CharacterModel._give_fists` | The Knight's hands: Meshy made them flat and open (no finger bones), so a grip went through the palm. `fist_r.glb` / `fist_l.glb` (closed gauntlets, built in the hand bone's frame around the sword's grip point) ride each hand through a mount node that follows the hand bone's un-shrunk pose; the open hand mesh is shrunk away by scaling the hand bones to ~0 after every animation frame (`_after_mixer`). Weapons attach to the mount too (`_mount_for`). `idle_rest` (authored in `tools/author_attack_anims.gd`: the sword lying over the right shoulder) plays after `PlayerMovement.REST_AFTER` s of standing about out of combat, and on the main menu. Look: `-- --handshot[=CLIP:T] [--body] [--equip=Greatsword]`. Test: `--only=fists`. |
| `game/hotbar_layout.gd` | Which skill is on which key. The seven assignable skills fill the six numbered slots and the right mouse button exactly, so a change is a swap (`HotbarLayout.assign`). The live layout is `GameSettings.hotbar_slots` / `hotbar_alt` (saved with the settings, shared with `SkillController.hotbar`); the HUD's click-a-slot picker (`Hud.open_picker`) and Settings > Controls dropdowns both change it. Test: `--only=hotbar`. |
| `game/gamepad.gd`, `game/input_setup.gd` | Controller support: sticks, aim, labels, rumble; all buttons are ordinary input actions, rebindable in Settings > Controls (keyboard/mouse and controller columns). |
| `game/loading_screen.gd` | Loading bar with real progress (assets load on background threads) and rotating messages; the menu's Play and the pause menu's Restart go through it. |
| `game/dev/` | Developer tooling, not part of the game. `dev_harness.gd` (`DevHarness`) only reads the arguments and dispatches: the self-test checks live in `suites/` (one file per area: skills, fireball, melee, knockdown, DS2 rules and powers, enemies, monsters, camera/input, HUD, loot, progression, build choices, town, world, quests), the screenshot/pose tools in `shots.gd`, the `--perf` and `--roadreturn` measurements in `perf.gd`. All extend `DevSuite` (`dev_suite.gd`: the short names for the game's parts, `expect`, and the helpers several suites share). A new check goes in the suite for its area, and in `ONLY_TESTS` (and the `_run_selftest` order, if it belongs in the default run). `town_shots.gd` (`TownShots`) holds the town's `--townshot`, `--xpdemo` and `--builddemo=` tools; `TownScene` adds it only when `--townshot` is given. |
| `game/night_sky.gd`, `game/night_sky.gdshader` | The night sky behind every scene (stars, a moon, drifting cloud streaks). `NightSky.apply(environment)`; it is painted on every direction, below the horizon too, because the 3/4 camera looks down and only sees it beyond the edge of the map. |
| Retired spinning attack | Cleave and Whirling are outside the playable kit. Maelstrom now stuns combo finisher hits, including Greatsword slam victims. The old spinning slash and inward pull visuals remain in `game/skill_fx.gd` for a future weapon with a circular attack. |
| `game/hud.gd`, `game/ui/hud_*.gd` | `Hud`: the combat HUD, drawn in code (hotbar, vessels, target and enemy bars, banners, death plate). Parts with their own state live beside it in `game/ui/`: `HudMinimap` (the round map, its own canvas item redrawn 20 times a second), `HudLootCards` (name plates over loot on the ground and the focused item's card) and `HudSkillPicker` (the hotbar's skill picker). The last two draw on the HUD's canvas from `Hud._draw`, so the drawing order is unchanged. |
| `game/ui_theme.gd` | The one UI look (worn metal, bronze trim, ember accent, muted bars): the Theme for menus plus drawing helpers for the HUD (`UiTheme.draw_panel`, `draw_bar`, `text` with a shadow). Use these for any new UI so it matches. Status readouts are an icon and a number, no label (`UiTheme.draw_stat`; the icons `assets/icons/ui/*.png` are rendered in Blender by `tools/blender/make_ui_icons.py`, the potion is the hotbar's own). |
| `game/destructible.gd`, `game/debris_chunk.gd` | `Destructible`: breakable props (barrels, carts, gravestones, braziers; see `STATS`). The arena builds them in `_place`. `Destructible.blast(tree, centre, radius, damage, dir, force)` is how anything breaks them: swings, the Greatsword slam, fireballs, bloater bursts and the powers (Whirling Strike, Flame Nexus, Detonation). | `game/loot_drop.gd` | `LootDrop`: an item lying on the ground after a monster died (tossed from the body, rarity glow and name, taken by clicking it or its name, or with the use key when in reach: nothing is picked up by walking over it; its name is a plate the HUD lays out so plates never overlap, `Hud._layout_loot_names`). The hero walks out through the road gate to hand it in (before that, staying in the gate abandons the job). `Arena` takes a rectangle (`half_x`, `half_z`; `Arena.bounds_of(tree)`); the minimap shows a window round the hero on a long arena. `-- --crypt [--at=x,z]` starts straight in it (developer tool). |
| `tools/` | Asset pipeline (Meshy generation, animation baking) and the generators for the `.tres` data files. |

The Tab/Back action toggles `game/character_view.gd`: a paused character preview in its own SubViewport, a paper doll of the nine worn places (DS2's weapon, shield, helm, body, gloves, boots, amulet and two rings; right-click/double-click or controller confirmation on a worn piece takes it off into the bag) and a scrollable bag with equip controls (right-click/double-click on a bag icon or name, or controller confirmation on a focused bag icon). Equipment swaps return the previous piece (and a shield pushed off by a two-handed weapon) to the bag; a piece the hero's class skill is too low for stays in the bag and he says what it needs. Controller focus stays in the bag after a swap. Focused input regression: `--only=inventoryequip`. `ItemTile`, `item_name.gd` and `item_button.gd` share the same stats/comparison card for mouse hover and controller focus. Ground item icon/name hit testing lives in `Hud`; town interaction cards are projected over their world target in `TownHud`.

The town gate uses `game/town/town_gate.gd` and `assets/models/town/working_gate/model.glb`. `tools/blender/make_working_gate.py` separates the original textured gate into its fixed arch and hinged leaves, preserving its UVs and materials. Approaching from either side opens it; moving away closes it. Focused verification: `--only=characterui`, `--only=lootui`, `--only=itemicons`.

The combat HUD uses health (lower left) and mana (lower right) vessels in `game/resource_orb.gd`, with Blender-rendered iron frames, glass and a 32-frame neutral liquid atlas in `assets/ui/vessels/`. `tools/blender/make_hud_vessels.py` builds and renders those assets plus the hotbar tray and skill bezels. `resource_orb.gdshader` blends the rendered frames and clips the fluid to live resource levels, with movement and resource-change slosh. `Hud.orb_rect`, `Hud.minimap_rect` and `hotbar_slot_size` share layout and mouse-hit geometry; the map is above the mana orb and stamina above the centered tray. Focused checks: `--only=orbhud`, `--only=uiblock`. Renderer preview: `-- --itemsheet --orbs`.

## Data first

Skills, enemies and items are Resources, not dictionaries in scripts.

* **Edit a number**: change the table in `tools/write_enemy_defs.py` / `write_skill_defs.py` / `write_item_defs.py`, run it, and the `.tres` files regenerate. (The `.tres` files can also be edited by hand or in the Godot inspector.)
* **Add an enemy**: add an entry to `write_enemy_defs.py` (stats, model path, `behavior`, `params`, spawn rules). If it needs new behaviour, write an `EnemyBehavior` subclass and add it to `EnemyBehaviors.create`. Waves pick it up from its spawn fields (`min_wave`, `base_count`, `per_wave`, `max_per_wave`, `spawn_mode`).
* **Add a skill**: add a `SkillDef` entry. Skills of an existing `kind` need no code; a new kind gets a branch in `SkillController`. A DS2 power is a `PowerDef` (`tools/write_power_defs.py`) plus, to make it playable, its effect in `PowerController` and a `kind = "power"` `SkillDef` for the hotbar.

* **Town data**: `tools/write_town_defs.py` writes `data/npcs` (`NpcDef`: Marlow the trader, Hale the keeper, Maren the healer, Cutter the recruit, Dorn the smith), `data/traits` (`TraitDef`) and `data/modifiers` (`RunModifierDef`). A run modifier (it belongs to the run, not to a kind of objective) is only multipliers (enemy spawn weights, health, speed, size, ambient light, fog, reward) applied by `RunDirector`, so adding one is a table entry. A new NPC is an entry plus a Meshy model (`tools/assets.json`, then bake its animations).
* **Town buildings and clutter**: `tools/blender/make_town_props.py` builds the forge, inn, chapel, granary and the small clutter (anvil, crates, wood pile, trough, drying rack, laundry line) into `assets/models/town/<name>/model.glb`, using the item script's palette and weathering plus a densify/warp and plank, shingle and grime pass so they match the Meshy cottages. They are placed by name `town/<name>` in `TownScene._build_town`; `Arena._place` switches their vertex colours on.
* **Town layout**: the static town is the scene `game/town/town_layout.tscn`, edited in Godot. `TownProp` nodes under `Props` (model, height, collides, lit; a preview shows in the editor) are the buildings, walls, lamps and clutter; `Marker3D`s under `Spots` mark the stone, board and stash, while `Stations` marks where people go (`drink`, `pray`, `work_<role>`). The gate is a physical trigger, not an interaction spot. `TownScene` places each prop through `Arena.place_prop` and deletes the markers; scripts keep the NPCs, interactions, simulation, state and transitions. NPC homes are still `NpcDef` data. To add a building, add a `TownProp` and set its `model_name`.
* **Weapon styles**: a weapon's moveset is `ItemDef.profile` (written by `PROFILES` in `tools/write_item_defs.py`), read through `PlayerStats.weapon_profile` (swing speed is the weapon's own `speed` stat, so the profile has no second speed knob): `recovery` (how fast the blade comes back after each blow), `weight` (stagger and knockback of the combo), `arc` and `arc_damage` (a basic swing also hits the other enemies inside that many degrees, for that share of the damage), `finisher_time`, `finisher` (`slam`: the combo's last blow shakes the ground in front) and `style` (the tooltip line). The falchion is quick and light, the longsword (an empty profile) is the baseline, the greatsword wide, heavy and slow; `SkillController._weapon_style_hits` and the three hooks in `start_skill`, `tick_busy` and `_apply_skill` are all that read them. Check with `--only=weaponstyle`.
* **Items** (Dungeon Siege II, `docs/ds2-combat-and-loot.md` 10-11): base items are data. `tools/write_item_defs.py` writes `data/items/*.tres` (`ItemDef`: id, name, slot, DS2 item type, armour class, its five item levels, model, icon; its numbers are DS2's weapon and armour curves at the item's level, `ItemDef.stats_at`), read through `ItemDb`. The numeric modifiers are `AffixDef` tiers (`tools/write_affix_defs.py`, `AffixDb`), the uniques and sets `UniqueDef` / `SetDef` (`tools/write_unique_defs.py`, `UniqueDb`). An item in the world is a Dictionary built by `Items.build` (`{def, level, slot, rarity, mods, unique, name, base, stats}`), but a save keeps only `{def, level, rarity, mods, unique}` via `Items.to_save` and rebuilds it with `Items.from_save`, so changing a base's numbers or model reaches every copy and an item whose base was removed is dropped on load instead of breaking the save. `Items` also rolls modifiers, drops (by monster tier, level window and magic find), shop stock and rewards, and says what an item needs (DS2: item level - 2 in Melee for weapons, the armour's class skill, the character level for jewellery). `PlayerStats.refresh` adds the worn gear (`gear_totals`: modifiers, uniques, set bonuses) into attributes, life, mana, armour, block, fire resistance and added fire; life steal and reflect are in `Player`. Save version 8 turned each item's tier into its item level. Checks: `--only=ds2items`, `--only=items`, `--only=loot`. New bases' models and icons: `tools/blender/make_items.py` (on a machine without a GPU set `CURSE_ICON_ENGINE=CYCLES`).
* **Road encounters**: `RoadEncounterRoster` owns fourteen authored groups (36 bodies), two or three enemies each. The first fourteen are level-one trivial fighters (7.56 HP); later levels rise only to three. One row means one body: pack multiplication and procedural gap filling are removed. Acid/bloater/priest/brute packs are absent; two later groups introduce a physical rock thrower using shared ranged spacing, without acid, splash, slowing or puddles. Nests wake only neighbours within 8 m and release two trivial fighters. Legacy uprising events cap at three reinforcements. The final small group retains clear reward/return-waystone handling.
* **Monster loot**: `MonsterLoot` rolls the complete DS2 common-tier alternatives (nothing, gold, health potion, mana potion, equipment), independently of active-member health. `RunDirector` no longer grants automatic kill gold and `Player` no longer spawns health-dependent kill orbs. Mana potions are shared campaign resources (`TownState.mana_potions`), defaulting to zero in older saves, usable on the active member via W/rebinding or the potion dock. Both potion types currently restore 60; tiered DS2 consumable definitions, container parity and full miniboss consumable loot remain unfinished.
* **Jobs**: a job is `{name, location, objective, modifiers, reward}`. `JobObjective` (`game/run/job_objective.gd`) is the only place that knows what an objective means (`clear_waves`, the test arena's wave loop, and `destroy_nest`, the Crypt Road's three nests, which has no waves: `uses_waves`, `ends_run_when_complete`; kill a target, rescue, hold a place and so on get a case there). The board, town HUD and `RunDirector` ask it to describe, count and finish a job, so none of them mention waves. Modifiers start at an objective *stage* (`min_stage`), which for `clear_waves` is the wave number.

## Tests and CI

`godot --headless --path . res://game/main.tscn -- --selftest` runs every check in `game/dev/suites/` (dispatched by `game/dev/dev_harness.gd`); each check calls `expect(label, condition)` and the process exits non-zero if any fail. `--only=NAME` runs one (`gibs`, `swarm`, `enemies`, `livepowers`, `impact`, `fireblast`, `balance`, `items`, `autoattack`). `tools/run_godot.sh LOG SECS -- <args>` runs Godot and kills it the moment a script/parse error appears instead of waiting for a timeout. `-- --timing` prints how long each stage of starting a run takes. `.github/workflows/selftest.yml` runs the full suite on every push and pull request.

Screenshot modes (`--skillshot=…`, `--enemyshot`, `--enemyfight`, `--clipsheet=…`, `--poses`, …) write PNGs to `%TEMP%` for judging visuals by eye.

## Assets

Model textures are imported GPU-compressed (VRAM) and capped at 1024 px (hero 2048): lossless 2k textures made every prop take ~280 ms to load. Large binaries (`*.glb`, `*.res`, `*.jpg`, audio, video) are stored with Git LFS (see `.gitattributes`). Dropped-item models are made in Blender (`tools/blender/make_items.py`, painted on the vertices, no textures); the Crypt Road's props (`nest`, `shrine`, `crypt_gate`, `cottage_ruin`, `iron_fence`, `corpse`, `road_gate`) come from `tools/blender/make_crypt_props.py` into `assets/models/crypt/` (place them as `crypt/<name>`). Blender 5.2's glTF exporter writes white vertex colours for every material but the first of a joined mesh, so that script exports one mesh object per material; on the Steam Deck Blender is a Flatpak (`~/.local/bin/blender`), so give it absolute paths. Models, rigs, animations and icons come from Meshy via `tools/meshy.py` / `meshy_icons.py`; `tools/bake_anims.gd` bakes animations into small `anims.res` files.
