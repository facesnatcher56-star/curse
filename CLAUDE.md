# Curse: notes for any agent working on this project

## 1. Art direction comes first: gritty and versatile

Every asset in this project, no matter what generates it (Meshy models, textures, animations and icons, images from any other
tool, shaders, particle effects, UI, even sound), must follow the art direction in [docs/ART_DIRECTION.md](docs/ART_DIRECTION.md).
Read it before generating or adding anything. It overrides tool defaults, convenience and any single prompt.

In short: **dark, grounded, worn-out fantasy. Gritty first (weathered, dirty, muted palette with warm ember accents, realistic
hand-painted PBR, heavy and physical, low-key lighting), and versatile (one material language across hero, enemies and props;
readable silhouettes from the far zoom; range without drifting out of the same world).**

- Generators: put prompts through `tools/art_direction.py` (`styled()`); `tools/meshy.py` and `tools/meshy_icons.py` already do.
  Any new generator integration must do the same.
- Never accept an asset that looks clean, glossy, cartoonish, neon or saturated. Regenerate it or fix it.
- Effects must be readable and physical (dust, debris, embers), not piles of overlapping sparkle. Never regenerate or restyle
  existing assets just to "improve" them without being asked.

## 2. How the project works

- Godot 4.8-dev2, GDScript. Click-to-move ARPG, fixed 3/4 camera (can orbit and zoom far out), controller supported. Layout and
  where things live: [ARCHITECTURE.md](ARCHITECTURE.md). Skills, enemies and affixes are data (`data/`, generated by
  `tools/write_*_defs.py`).
- Run Godot through `tools/run_godot.sh LOG SECS -- <godot args>`: it kills the run the moment a script or parse error appears
  instead of waiting for a timeout. Self-test: `-- --selftest [--only=NAME]` (exit code non-zero on failure). A new `class_name`
  needs `godot --headless --import` once.
- Test only what you added or changed (`--only=NAME`, short timeout) and add a test only for new behaviour. Do not run the full suite after each change or re-run it chasing flaky old checks (it takes minutes); run it only when the owner asks. Stop at the first error.
- Models and other binaries are in Git LFS (see `.gitattributes`). Do not force-push, and do not commit secrets (the Meshy key
  lives in `~/.meshy/key` or `MESHY_API_KEY`, never in the repo).
- Sound: only recordings the owner supplied are in the game (`assets/audio/`, credits in `assets/audio/CREDITS.md`). Do not add
  synthesised or generated sound without being asked.
- The owner's reference game is Dungeon Siege 2; `docs/ds2-combat-and-loot.md` is the write-up of its rules.
- The owner's other reference game is Zombasite (Soldak): `docs/zombasite-world-and-npcs.md` covers its towns, NPCs, clans, factions, level/world modifiers, monster affixes and what monsters do outside combat. `tools/zombasite_dump.py` reads the game's own data files if you need more (nothing from the game is stored in the repo).
- The town hub (`game/town/`, see ARCHITECTURE.md) sits between runs: Play opens it, its gate starts a job, and town data (NPCs, traits, wave modifiers) is generated by `tools/write_town_defs.py`. Meshy credits are limited: check `python tools/meshy.py balance` before and after any generation, and do not regenerate existing town assets.
- Blender 5.1 is installed (`C:/Program Files/Blender Foundation/Blender 5.1/blender.exe`) and may be used for any model the game needs, without asking: items are built by `tools/blender/make_items.py` (run it with `--background --python`, then `godot --headless --import`). The Crypt Road's props are `tools/blender/make_crypt_props.py` (see ARCHITECTURE.md for the 5.2 exporter workaround and the Flatpak note). Same art direction as everything else. Godot leaves the first material of a vertex-coloured GLB without vertex colours: switch them on at load (see `LootDrop._use_vertex_colours`).
- Mouse and controller are both first-class: any new input must be rebindable (Settings > Controls) and work on a controller.
